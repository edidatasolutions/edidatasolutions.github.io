Packages

Each package answers one operational question, ships a simulator with known truth, and reports its own validation: how often it is right, and where it is not.

Rater-mediated exams

decisionfacets

Would this candidate have passed with a different set of raters?

Counterfactual pass probabilities for oral exams, OSCEs and essay scoring under the many-facet Rasch model, computed exactly for the assigned panel, an average panel and a random panel, plus a split of misclassification into measurement error and rater assignment.

Validation: estimates from standard MFRM software recovered rater-dependent candidates as well as an oracle that knows the true parameters (71%), and severity-adjusted scoring removed rater dependence entirely.

Test security

retestR

Did this repeater gain more than they should have?

Models each repeat candidate's expected gain from data preknowledge cannot touch, then flags departures using exposed-item performance and response speed, with a bootstrap-calibrated false-positive rate for every flag.

Validation: flagged 98.9% of preknowledge cases at a 1.03% false-positive rate; raw-gain flagging of the same number caught 42% and flagged about nine times as many honest remediated candidates.

Item development

coldstart

How do we calibrate AI-generated items before we have pretest seats?

Predicts each new item's difficulty from its features (text embeddings, attributes, template family) with honest uncertainty, uses the prediction as a robust prior, plans pretest sample sizes, and withdraws priors from template families whose predictions fail.

Validation: with predicted priors, 25 pretest responses per item did about what 50 do without them, and 90% predictive intervals covered 90% of true difficulties.

Item bank maintenance

driftwatch

Not "did it drift?" but when, how, and what should we do?

Sequential CUSUM monitoring of item parameter drift for continuous testing and pre-equated banks: change points, gradual versus abrupt drift, thresholds tuned on the program's own design, score impact, and an audit log of recommended actions.

Validation: design-calibrated thresholds held false alarms at 0.86% against a 1% target (4.0% with a textbook threshold) and detected 99% of abrupt drift a median of four windows after onset.

Assessment systems

throughyear

How should interim results be used in a through-year system?

Links interims to the summative scale with measurement error carried forward, evaluates prior-informed multistage routing, and checks fairness for late enrollers, low scorers and students who grow after the last interim.

Validation: interim priors raised routing accuracy from 70% to 84%, but using them to score under-reported late-growing students by 0.29 logits: route with them, do not score with them.

Fairness and comparability

transDIF

Does a score mean the same thing in both languages?

Comparability for translated and adapted exams with small translated-language groups: robust linking through the densest cluster of items, empirical-Bayes DIF detection with false-discovery control, pass-rate impact, and item-feature explanations for translators.

Validation: on 60-item tests, robust linking was essentially unbiased where mean linking was not, and DIF detection kept false discoveries below its 10% target with more power than Mantel–Haenszel.

Install

All six packages are on CRAN and depend only on base R.

install.packages(c("decisionfacets", "retestR", "coldstart",
                   "driftwatch", "throughyear", "transDIF"))
